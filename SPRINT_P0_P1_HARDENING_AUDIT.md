# Calisthenics Coach — Sprint P0/P1 Hardening

## Implemented

### P0
1. **No direct progression mutation from PromotionPanel**
   - `PromotionPanel` is now read-only.
   - Progression changes happen only from a persisted `CoachProposal` after explicit human acceptance.

2. **Quality unknown is truly unknown**
   - Quality is stored structurally on `WorkoutLog.result.quality`.
   - `qualityScore()` returns `undefined` when quality was not recorded.
   - Clean-required progression cannot pass without recorded quality.
   - The old `82%` implicit quality fallback is removed.

3. **Readiness reaches the engine**
   - `coachingRecord()` can carry the parent `SessionSummary.readiness`.
   - Proposal generation passes the session into the engine.
   - A progression proposal is blocked when readiness gates are missing, blocked, or cautionary.

4. **Target progression vs variant mastery are explicit**
   - `ProgressionSpec.targetProgression` and `ProgressionSpec.variantMastery` are now separate.
   - `progressionSpecForBlock()` is the canonical runtime builder.

5. **Variant identity is explicit**
   - `WorkoutLog.variantId` added.
   - `ProgramOverride.variantId` added.
   - Previous exposure and PR comparisons prefer `variantId` over display name.
   - `CoachProposal.variantId` is persisted for variant promotions.

6. **EMOM qualification is separate from today's ceiling**
   - Qualification uses the lower bound of the prescribed range rather than requiring the top target every minute.
   - Stability still requires bounded drop-off / CV / last-vs-first.

7. **Coaching Engine test suite**
   - Added `tests/coachingEngine.test.ts`.
   - Covers:
     - clean Front Touch progression;
     - unknown quality blocking clean-required progression;
     - unstable EMOM rejection;
     - stable EMOM acceptance;
     - OAP R/L qualification;
     - readiness failure;
     - missing readiness blocking progression;
     - qualifying streak behavior.

### P1
8. **`any` removed from `skillIntelligence.ts`**
   - Replaced with `WorkoutLog` / `SessionSummary` domain types.
   - No `any` remains in the file.

9. **Quality no longer encoded in notes**
   - Static-skill execution quality is stored in `result.quality`.
   - `coachingEngine` reads only the structured field.

10. **Progression ladder access unified**
    - `getProgressionLadder()` is the single access helper for rung selection.
    - The decision layer no longer reaches into ladder data directly.

11. **`block.detail` is not a quality source**
    - Coaching criteria are generated by `criteriaForBlock()` / `progressionSpecForBlock()`.
    - `detail` is treated as display/context text.

12. **Readiness is a structured gate**
    - `pain`, `sleep`, `energy`, and `overall` are represented explicitly as PASS/BLOCK/UNKNOWN.
    - `allowProgression` is derived from the gates, not from score alone.

## Known environment limitation

A full `npm run build` cannot be truthfully reported from this container because the project dependencies (`react`, `lucide-react`, Supabase, Vite) are not installed in the execution environment. The user's local `npm run build` remains the authoritative full-build check.

## Remaining architecture risk after this sprint

The next hardening step should be a single domain-level `ExerciseExposureKey` (`exerciseId + variantId`) used throughout history, PRs, previous exposure, proposals, and coach analytics. This sprint establishes the fields and uses them in the most sensitive paths, but legacy fallbacks remain for old local data.
