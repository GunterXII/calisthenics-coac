# Calisthenics Coach V19.1 — Domain Hardening

## P0

1. **Single domain ownership**
   - `ProgramOverride`, `CoachProposal`, `CoachDecision`, and `CurrentVariantState` now live in `src/types.ts`.
   - `storage.ts` imports/re-exports those types and no longer defines persistence-specific copies.

2. **WorkoutLog session identity**
   - `WorkoutLog.sessionId` is required.
   - Storage normalizes legacy logs to deterministic `legacy:<logId>` IDs.
   - Session save/replace/merge paths stamp logs with the owning session ID.

3. **Atomic + idempotent proposal acceptance**
   - `acceptCoachProposalAtomically()` applies proposal status, override, variant state, and coach decision as one guarded local mutation.
   - Already accepted/rejected proposals are no-ops.
   - Snapshot rollback is used if a write fails.

4. **Unknown remains unknown**
   - Fatigue controls default to blank.
   - Static-skill quality defaults to undefined and is only stored when explicitly selected.
   - Coaching quality calculations already return undefined when quality is absent.

5. **No UI copy as coaching source-of-truth**
   - `block.detail` is no longer parsed for progression RIR rules.
   - Progression metadata is read from the progression registry.

6. **ProgressionSpec is authoritative for next target**
   - `PROGRESSION_SPECS` is the single registry containing target increment metadata and the variant ladder.
   - `PROGRESSIONS` is only a derived compatibility view.
   - `nextTargetFromSpec()` is the single next-target calculator.

7. **Centralized exposure identity**
   - Added `ExerciseExposureKey` plus `exerciseExposureKeyString()`.
   - Previous-exposure/history comparisons use exercise + variant identity rather than display names.

## P1

8. **Unified progression registry**
   - Removed the separate `PROGRESSION_LADDERS` data source.
   - Ladder data now lives inside `PROGRESSION_SPECS`.

9. **Skill Intelligence refocused**
   - Skill Intelligence delegates qualification and readiness interpretation to the central coaching engine instead of maintaining an independent qualification algorithm.

10. **Expanded automated tests**
   - Coaching engine tests retained and extended with domain hardening tests.
   - Added backup migration checks, exposure-key checks, target progression checks, and proposal idempotency/atomicity checks.

11. **Reduced `any` in domain/persistence layers**
   - Removed `any` from `skillIntelligence.ts` and the core storage model helpers.
   - `saveDraft` now uses `WorkoutDraft`.

12. **Backup migration coverage**
   - Backup schema is now version 10.
   - Versions 8/9 are migrated on import with normalized session IDs and variant IDs.
