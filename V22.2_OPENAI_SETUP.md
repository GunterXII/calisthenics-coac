# V22.2 — OpenAI Coach setup

## What is already deployed

The Supabase Edge Function `coach-chat` is deployed to project `tpjpnpkwhosluiucbdzx` with JWT verification enabled.

The browser sends the structured Coach context and read-only tool definitions to the function. The function calls the OpenAI Responses API server-side, so the OpenAI key is never bundled into the frontend.

## 1. Frontend `.env`

Create `.env` in the project root:

```env
VITE_SUPABASE_URL=https://tpjpnpkwhosluiucbdzx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

Do not put `OPENAI_API_KEY` in this file.

## 2. OpenAI key

Create an API key in your OpenAI account and store it as a Supabase Edge Function secret named:

`OPENAI_API_KEY`

Optional model override:

`OPENAI_MODEL=gpt-5.6-luna`

The function defaults to `gpt-5.6-luna` when `OPENAI_MODEL` is absent.

### Dashboard

Supabase Dashboard → Edge Functions → Secrets → add:

- `OPENAI_API_KEY` = your OpenAI API key
- optionally `OPENAI_MODEL` = `gpt-5.6-luna`

### CLI alternative

```powershell
supabase secrets set OPENAI_API_KEY=YOUR_OPENAI_API_KEY --project-ref tpjpnpkwhosluiucbdzx
supabase secrets set OPENAI_MODEL=gpt-5.6-luna --project-ref tpjpnpkwhosluiucbdzx
```

Never commit the OpenAI key or send it to the browser.

## 3. Authentication

`coach-chat` has `verify_jwt=true`. The user must therefore be signed in to the Supabase project when invoking the Coach. The existing frontend already uses the Supabase auth session, and `supabase.functions.invoke()` sends the session authorization header.

## 4. Run locally

```powershell
npm install
npm run build
npm run dev
```

Open the local Vite URL and sign in.

## 5. Verify that the real AI path is active

Ask the Coach:

> Come sta andando la mia OAP? Usa i dati reali delle ultime sessioni e dimmi cosa cambieresti, se cambieresti qualcosa.

Then ask:

> Quanto volume produttivo sto facendo per chest, triceps, front delts e side delts e come lo aumenteresti senza compromettere OAP, FL Pull-Up e Front Lever Touch?

A real AI response should be conversational and specific, not the fixed local fallback phrase.

The UI still falls back to the deterministic local Coach if the Edge Function is unavailable. That fallback is intentional for offline/failed-backend operation, but for V22.2 validation the goal is to see `source: ai` in the response path.
