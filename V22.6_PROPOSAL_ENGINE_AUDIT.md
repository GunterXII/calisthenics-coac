# V22.6 — Proposal Engine Audit

## Fixed
- Day scoping now carries the day onto every generated ExerciseBlock. Previously `Push A`/`Push B`/etc. could fail to scope because the blocks themselves had no `day` property, causing fallback to the first block (Pike Push-up).
- Generic hypertrophy/volume proposals now prefer a support hypertrophy block that directly overlaps a LOW hypertrophy muscle, then other support/secondary hypertrophy work, before primary strength/skill blocks.
- This prevents an accumulation-phase request to fill an accessory hypertrophy gap from automatically spending recovery budget on a primary skill/strength movement.

## Expected Push A behavior
With LOW chest/triceps/front delts/side delts and a request to increase hypertrophy, the selector should prefer `lat-a` when the explicit request is generic and the day is Push A, because it directly addresses the LOW side delts with low fatigue. If the request explicitly names chest or triceps, selection should target the corresponding block/overlap instead of blindly selecting Pike Push-up.

## Architecture rule
AI chooses/justifies the intervention; deterministic engines calculate impact, fatigue, weekly utilization and warnings. The UI should render those deterministic values as evidence.
