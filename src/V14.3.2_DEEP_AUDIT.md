# V14.3.2 Deep Audit

## Fixed
- Exercise player state now remounts per exercise via `key={block.id}`. This fixes stale SetBlock/SideSetBlock state when moving from OAP → Assisted OAP → Archer or between consecutive same-type blocks.
- Parent workout advance is guarded against accidental double taps.
- Static-skill stop is guarded against timer/manual-stop races.
- Front Touch now has an explicit 8 sec coach target instead of the non-numeric `Best hold` placeholder, so the isometric target logic is meaningful.
- Accepted/promoted progressions are persisted as program overrides and synchronized, so they survive refresh/device sync rather than existing only in local variant state.
- Coach session notes are uploaded after save, keeping local and remote session data consistent.
- Program Editor undo/reset now re-syncs the restored override.
- Removed the dynamic storage import in backend mobility sync to avoid the Rollup chunk warning caused by mixed static/dynamic imports.

## Audit observations
- The remaining main code file is intentionally monolithic for stability; no risky structural refactor was included.
- Today-target values remain device-local by design and are not yet a remote coach prescription.
- Mobility dynamic exercises use a visible timer plus rep counter; the timer is the pacing mechanism, while reps are recorded for feedback.
- No background push notification implementation was added in this patch.

## Validation
- Static source review completed across `main.tsx`, `program.ts`, `storage.ts`, `backend.ts`, `mobility.ts`, `types.ts`, and Vite config.
