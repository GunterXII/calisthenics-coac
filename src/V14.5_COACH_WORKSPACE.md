# V14.5 — Coach Workspace / Plan Control

## What is now implemented

- Role-aware boot: athlete accounts keep the existing Today / Plan / Reports flow; coach accounts open the dedicated Coach Workspace.
- Coach roster comes from `coach_relationships` with RLS enforcement.
- Coach can select an athlete and inspect the active program plus recent workout sessions.
- Coach can edit any programmed block using the prepared exercise catalog and compatible skill / movement-pattern filtering.
- Coach edits persist to the athlete's `program_blocks.override_payload` and are pulled by the athlete on the next sync/load.
- Resetting an exercise removes the override and returns the compiled default.
- Coach changes create `program_decisions` and `program_audit_log` entries and increment the program version.
- Athlete can explicitly link to a coach with the coach's short code.
- Coach code is generated only for accounts whose `profiles.role = 'coach'`.
- Workout history remains immutable; coach edits affect future prescriptions only.

## Account setup

1. Create the coach account with the normal Sign Up flow.
2. In Supabase SQL Editor, set that profile's role to `coach` (this is intentionally not self-service):
   `update public.profiles set role = 'coach' where id = 'YOUR_AUTH_USER_UUID';`
3. Sign in as the coach. The Coach Workspace generates the coach code.
4. Create/sign in to the athlete account.
5. In the athlete Plan page, enter the coach code under Coach Connection.
6. The athlete then appears in the coach roster.

## Database

`supabase/migrations/006_coach_access.sql` adds:

- `profiles.coach_code`
- secure coach-code generation
- secure athlete-to-coach linking
- secure unlink RPC
- authenticated-only execution grants
- explicit authenticated execution for `is_coach_for`, required by the RLS policies

The same migration is idempotent and can be applied after the existing V14.4 migrations.
