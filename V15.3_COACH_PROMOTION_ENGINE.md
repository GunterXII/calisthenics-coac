# V15.3 — Coach Promotion Engine

## Goal
Turn a Skill Graph `READY` state into a safe, human-reviewed program change.

## Flow
Skill Graph → READY → Review Promotion → atomic backend promotion → decision/audit → athlete sees next rung on next load.

## Identity rule
Every promoted rung receives a new `exercise_id` instance. The canonical catalog id lives in `override_payload.catalogExerciseId`. This prevents historical workout logs from being reclassified as the new skill variant.

## Safety
- Coach relationship is checked server-side.
- Promotion is atomic.
- Historical logs are untouched.
- Current block is replaced only in the future program.
- Decision and audit records are written in the same transaction.
- No automatic promotion occurs from Skill Intelligence alone.

## Evidence basis
The product intentionally uses an evidence-gated, human-reviewed progression model rather than automatic advancement. The 2026 ACSM resistance-training position stand emphasizes individualized programming, gradual progression and that more complexity is not inherently better. Recent autoregulation reviews support using performance/readiness feedback to adjust programming rather than relying only on fixed prescriptions.
